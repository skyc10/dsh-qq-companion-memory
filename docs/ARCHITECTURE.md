# 架构与后期调整框架

状态：首版已实现并完成构建／静态核对，运行性验收待执行。需求依据 [开发计划](../PLAN.md)，接口以[实施契约](IMPLEMENTATION.md)为准，决策分类见 [决策记录](DECISIONS.md)。

## 分层与依赖

采用单个插件，领域对象、业务流程、策略、适配和界面分层。领域层不依赖 DSH、QQ、HTTP 或 SQLite；业务流程使用接口，适配层负责具体调用。入口仅装配依赖和管理生命周期，不堆积业务判断。

| 目录 | 职责 | 典型后期调整 |
| --- | --- | --- |
| `src/domain/` | 范围、预算估算、稳定交流段及共享领域函数 | 新增状态或分段规则 |
| `src/application/` | 采集、绑定、召回、管理、导入、备份恢复 | 调整业务用例 |
| `src/learning/` | 材料、调度、配额、模板、严格输出、证据、人格版本 | 更换学习策略 |
| `src/adapters/dsh/` | 模型、上下文、HTTP 与管理页接入 | 适配 DSH 版本 |
| `integration/` | QQ 可信事件、角色、绑定、发送回执和接管 | 适配固定桥接版本 |
| `src/storage/` | SQLite、事务、历史、删除、一致性快照 | 索引或迁移 |
| `src/config/` | 默认值、结构、覆盖及约束 | 调整已授权阈值 |
| `src/client/` | 管理页与同源接口调用 | 页面与交互 |
| `scripts/` | 构建、语法检查、离线接线、旧材料准备与打包 | 发布工具 |

当前实现不引入微服务或多套平行真相。

## 数据流

可信 QQ 事件 → 持久采集 → 按角色与范围处理 → 记忆／候选／证据。

当前回合身份 → 权限过滤 → 相关检索 → 策略与预算 → DSH 上下文 → 发送反馈。

候选＋新证据＋试用记录＋反馈 → 采纳判断 → 范围规则或角色人格版本。

管理变更 → 身份授权＋预期版本 → 事务与审计 → 失效缓存 → 下一轮有效快照。

聊天不等待后台学习完成。采集先尝试持久化；存储故障必须报告，不能声称无限制保证不丢消息。持久队列容量、满载和重放规则在实现时明确记录。

## 接口契约

| 接口 | 输入／输出约定 |
| --- | --- |
| `EventIngestor` | 接收规范化可信事件，返回接收、重复或失败状态；不得从正文补全身份 |
| `IdentityResolver` | 按稳定角色 ID、会话绑定版本及真实 QQ 信息返回范围；不明身份关闭长期写入 |
| `MemoryRepository` | 带范围查询、版本变更、事务、删除标记；不提供默认全范围查询给普通回合 |
| `LearningModel` | 指定模型、模板、预算、材料 ID；输出完整结构、完成原因与实际用量；不自选收费替代模型 |
| `RecallPolicy` | 输入已授权候选与回合上下文，返回入选、排除、理由及预算信息 |
| `EvidencePolicy` | 返回独立证据单位、日期、冲突、支持和排除理由；不把模型自评分当概率 |
| `AdoptionPolicy` | 返回可试用／可采纳与未满足项，不直接执行数据库写入 |
| `Clock` | 提供当前时间及上海日界线，避免策略各自解释日期 |
| `UsageLedger` | 请求预留、发送、完成、失败与不确定状态；未知用量不伪造为零 |
| `BackupStore` | 一致性快照、清单、保留期与恢复预览；恢复须人工确认 |

接口先为实际需求服务，避免提前实现不存在的替代提供商。

### 规范化事件

基本字段：`schemaVersion`、`eventId`、`botQQ`、`characterId`、`conversationKey`、`groupId`、`senderQQ`、`messageId`、`occurredAt`、`receivedAt`、`content`、`quoteRefs`、`sourceKind`、`bindingVersion`。

QQ 与群号规范为字符串；绑定版本随事件固定。接收端验证调用者和范围，不能相信任意模型提交的身份字段。幂等键包含来源和会话范围，不只使用消息文本或时间。若真实消息 ID 缺失，标记不可可靠去重，不将重放当新证据。

### 管理变更

携带 `requestId`、目标 ID、目标范围、`expectedVersion`、动作和原因。操作者由认证通道确定，不信任请求自填管理员身份。冲突时返回当前版本，避免覆盖较新更改。变更、审计与失效标记在事务内一致提交。

## 配置与可替换策略

覆盖顺序：内置默认 → 实例 → 角色 → 明确允许的会话范围。每个配置键声明类型、默认值、允许层级、生效时机和约束。

| 配置组 | 内容 |
| --- | --- |
| `memory` | 近期窗口、保护类别、淡化与召回策略 |
| `learning` | T1–T5、批次、并发、重试与有效消息策略 |
| `budget` | T6–T8、自动预算、手动上限及模型能力覆盖 |
| `evidence` | S1–S6、连续交流划分、应用判定及反馈规则 |
| `models` | 实例模型、角色覆盖、跟随当前聊天模型 |
| `sharing` | 字段、源引用、范围与缓存失效 |
| `backup` | 路径、时刻、时区、保留天数 |
| `features` | 采集、记忆、学习、试用、自动采纳和旧能力接管开关 |

权限、角色隔离、私聊隔离和全局额度不能被局部配置放宽。共享范围变更必须经过显式管理动作和审计，不能通过普通配置覆盖偷偷扩散。模型禁用收费回退是硬边界。

普通策略下一次调度／装配生效；数据目录等标为需重启。任务记录创建时与实际请求时的配置版本，执行前复核当前权限、额度和源状态。安全收紧与停用优先于旧任务配置。

提示模板、输出 schema 和业务流程分别存放，记录版本。模型上下文或输出能力未知时要求明确上限，不猜容量；不能用字符数假装精确 token 用量。

## 状态与一致性

- 候选、试用、采纳、暂停、驳回有显式转换及原因；冲突暂停自动采纳。
- 注入记录和实际应用记录分表或分类型；无法确认应用不计入 S4。
- 回退创建新的恢复版本，保留父版本与历史；范围表达版本和角色人格版本分开。
- 关联共享引用源 ID；源禁用、删除或撤销使缓存和有效上下文快照失效。
- 原文删除、可撤销删除、审计元信息、备份残留分开表达。明确删除不能通过通用历史接口继续暴露原文；撤销所需内容只在获授权的受控保留机制中恢复。
- 调度游标仅在对应完整处理事务成功后推进；失败、额度不足和模型截断保留材料。
- 配额按真实请求归属上海日期记录；请求状态不确定时保守记账并显示，不自动假定可返还。
- 初次任务、重试与积压分批如何使用间隔属于实现细则，编码前记录，避免借重试绕过间隔或把一次批处理误拆成多次触发。

## 版本与迁移

插件、数据库、配置、事件、提炼结果与提示模板分别版本化。数据库采用有序迁移，升级前一致性备份；迁移失败不继续挂载新业务。旧数据保留来源，不能确认归属的条目隔离待处理。

回退旧插件前检查数据库兼容范围；不承诺随意安装旧版本即可读取新数据。必要时从升级前快照恢复，并展示恢复期间会丢失或复活的内容，待人工确认。

## 修改操作表

| 想调整的内容 | 修改位置 | 必须检查的影响 |
| --- | --- | --- |
| 消息门槛、时间、配额 | 配置＋触发策略 | 积压、已有任务、跨日记账 |
| 淡化、召回、注入 | 策略＋配置 | 保护内容、权限过滤、T8、旧快照 |
| 模型或学习提示 | 模型适配＋模板版本 | 容量、完整输出、用量、费用边界 |
| 证据、试用、采纳 | 证据／采纳策略 | 已有候选重新评估，不追溯伪造证据 |
| QQ 或 DSH 升级 | 对应适配层 | 身份、生命周期、上下文和鉴权 |
| 新字段或索引 | 存储迁移＋契约 | 向后兼容、备份、导入和回退 |
| 管理页面 | 客户端＋API | 服务端仍独立校验权限与版本 |

调整时更新需求和决策记录，列出影响范围与迁移方式。测试编写和执行需要明确授权，源码／文档审查不能标记成运行性验收通过。
