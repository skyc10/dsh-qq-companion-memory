# 决策与变更记录

更新：2026-10-27。需求数值以 [开发计划](../PLAN.md) 为准；模块及兼容规则见 [架构](ARCHITECTURE.md)。

## 已确认的产品决策

| 决策 | 内容 |
| --- | --- |
| 插件形态 | 一个插件，记忆与学习独立管理，共用基础能力 |
| 学习方式 | 提炼、证据、检索与提示指导，不训练权重 |
| 身份 | 角色独立；长期归属不使用 DSH Session.id |
| 跨群认识 | 同角色按 QQ 共享个人认识，保留群内补充；私聊默认隔离 |
| 原文 | 保存至用户删除，淡化不等于删除 |
| 参数 | 保留计划中的 T1–T8、S1–S6、R1–R8，不静默修改 |
| 成长 | 小幅人格变化、有来源与快照，可回退且保留经历 |
| 失败处理 | 保留材料与任务，不阻塞聊天，不自动回退收费模型 |
| 权限 | 可信身份与管理员白名单；普通私聊反馈只影响本人 |
| 备份 | 每日、保留 14 天、恢复人工确认 |
| 开发位置 | 工作区根目录的本插件目录，完整计划保存在目录内 |
| 修改能力 | 配置集中、策略独立、适配解耦、接口与数据分别版本化 |

## 已审阅的实施方案

以下是技术默认方案，不等同于新增产品要求。

| 项目 | 方案及理由 |
| --- | --- |
| 存储 | SQLite 同步事务；使用 Node 24 `node:sqlite`，专用实例的实际运行性待验收 |
| 数据根 | 专用实例 `$DSH_HOME/qq-companion-memory`，支持配置覆盖 |
| 分层 | domain、application、adapters、storage、config、learning、client |
| 注入 | DSH `systemPrompt.context`，记录有效快照与实际召回 |
| 内部接入 | 桥接薄适配层传递可信规范化事件，接口鉴权且幂等 |
| 归档 | 数据库日期分组与导出，不维护两套可独立修改的真相 |
| 旧数据 | 可确认归属才导入，否则待确认；不沿用历史全会话合并 |
| 开关 | 采集、召回、候选学习、自动采纳逐阶段开启 |
| 群成员反馈 | 首版记录待处理，不直接修改共享、群规则或人格；具体产品细则未选定 |

## 本轮实施口径

- 连续指数淡化：近期窗口后衰减，半衰期独立配置，技术默认 30 天；不删除原文。连续交流默认间隔 30 分钟，事务内持久保存段边界与合并关系，删源不拆段，迟到消息只能合并，不按 Session 或日期切段；缺失段信息的旧材料才保守按日归并。
- 版本管理使用 GitHub 私有仓库 skyc10/dsh-qq-companion-memory；源码与锁文件入库，依赖、数据库、凭据及生成产物排除。
- 同范围每次只处理一个批次；首条有效消息建立首次计时，后续积压与失败重试均遵守最短间隔并计额度。未知模型容量要求人工上限，未知实际用量与价格保持未知。
- 成功发送不直接等于已应用；先保留 message_id 与原文，再核验候选及发送片段。沉默、普通感谢不构成明确正向反馈。
- 源编辑只更新已授权共享字段；源停用／删除暂停引用及派生项。删除清除本插件可查询历史副本，受控撤销窗口默认 7 天；旧备份与 DSH 会话快照仍可能保留旧内容。
- 服务端以 ESM JavaScript 实现并做构建／语法静态检查；先前 TypeScript 是可选技术方案，当前不引入虚假的类型检查通过声明。
- 专用实例固定 DSH rc.2；宿主 rc.3 的 API 调查只作对照，实际兼容及 SQLite 运行性仍待专用实例验收。
- 2026-10-27 重新按原计划复核，修正逐候选应用核验、自动召回预算与聊天／记忆／学习用量分列；补全事实时效、后来替代及事实冲突处理。
- 学习保留完整消息，先缩批次；首条仍超预算时暂停并保留游标。输出上限取模型能力与 `512+批次条数×96` 的较小值；截断仍整批不应用。模板／输出结构升级为 `/3`。
- 群绑定参与者由桥接可信事件补充；普通私聊负反馈覆盖已采纳规则，角色人格仅对该用户屏蔽对应变化。
- 2026-10-27后续审计核对：重要性为1至5整数，类型默认经历1、事实/偏好/关系3、承诺4、边界5、未知类型1；人工和模型可给出合法数值，记录来源。模板/输出升至 `/4`。现有条目不自动回填或重排；编辑未改数值时保留重要性来源，清除数值则按当前类型生成默认值。回退本地源码即可撤销生成策略，不修改已发布 v0.1.1。
- 同日修正：capture 只管事件采集，可信 QQ 会话用量观察不依赖该开关；历史查看沿用版本游标；归档显示与导出统一上海日。群来源档案由管理员创建/编辑时规范化可见性，旧记录需编辑确认，不推测来源或批量扩散。
- 后续用户要求完成修复、编写待测清单并建设WebUI：基于既有同源页面补充真实数据库计数总览、待处理入口、表单/JSON双模式、分区深链接和响应式/键盘交互；不另建认证、端口或数据存储。配置开关继续由DSH插件配置管理。
- 补查启用链路，将旧记录的规范化结果随显式启用实际写回；旧失效材料拒绝直接启用，人工候选补类型范围与匹配元数据。以上无批量迁移；当前仍未执行任何业务/浏览器测试，交由用户另派agent按待测清单验收。
